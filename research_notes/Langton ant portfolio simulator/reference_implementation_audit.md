# Reference Implementation Audit: Langton's Ant / Turmite Web Simulators

Research date: 2026-10-17. Both reference sites were fetched directly (HTML + all linked JS). GitHub data from the GitHub Search/REST API on the same date (star counts and push dates reflect that snapshot). Every claim below is from a primary source I fetched unless flagged as an inference.

## langtonant.com — what it actually offers

### Takeaway
langtonant.com is a minimal 2017-era vanilla JS/Canvas demo (source: coder369/langtons-ant, 18★, last pushed 2017-07-03) with preset LR behaviors, custom L/R-only rule strings, fixed square grids up to 5000×5000, and a steps/delay selector — but it has no play/pause/step/reset buttons at all, resets the simulation on every option change, assigns random (non-curated) colors to most presets, and has no mobile viewport, no zoom/pan, no sharing, and no export. It is trivially beatable on interaction design.

### Cited Findings
- Source code link on the page points to https://github.com/coder369/langtons-ant ("An HTML5 vanilla JS implementation of Langton's Ant"); GitHub shows 18 stars, language JavaScript, last pushed 2017-07-03, homepage listed as https://langtons-ant-amber.vercel.app — [GitHub repo](https://github.com/coder369/langtons-ant); [GitHub API search](https://api.github.com/search/repositories?q=langtons-ant); [langtonant.com](https://langtonant.com/)
- Controls panel ("Simulation Options"): Starting Orientation select (Up/Right/Down/Left), Behavior select (populated by JS), a hidden Custom Behavior text input revealed only when "Custom" is chosen, Grid Size select (50×50, 150×150 [default], 250×250, 500×500, 1000×1000, 5000×5000), "Steps per Refresh" select (1 [default], 10, 50, 100, 250, 500 … 500,000), "Delay per Refresh" select (1 ms [default], 50 ms, 250 ms, 500 ms, 1 s, 2 s, 5 s) — [langtonant.com HTML](https://langtonant.com/)
- Built-in behavior presets (from the minified JS `Simulation()` options object): `RL` (the classic ant, hardcoded colors `#5f5` green / `#f55` red), `RLR`, `LLRR`, `RLLR`, `LRRRRRLLR`, `LLRRRLRLRLLR`, `RRLLLRLLLRRR`; every preset other than RL gets its colors from a random hex-color generator (deduplicated per selection), not a curated palette — [moore-sof.langton-ant.min.js](https://langtonant.com/js/moore-sof.langton-ant.min.js)
- Custom rules accept only the letters L and R: a `keydown` filter blocks every key except delete/backspace/tab/arrows/L/R (keyCodes 76, 82, 108, 114), so custom behavior is an arbitrary-length LR string (multi-color ant in the Wikipedia "extension to multiple colors" sense) but supports no U-turn, no no-turn, no states — [langtonant.com inline script](https://langtonant.com/)
- There are no play/pause/step/reset controls anywhere in the page: the sim auto-starts on load (`new Simulation(); sim.run()`), and every control change calls `sim.run()`, whose first act is a full reset (clear interval, wipe iteration counter, re-init grid and ant). Changing grid size or behavior mid-run destroys progress — [langtonant.com HTML + min.js](https://langtonant.com/)
- The grid is fixed and non-wrapping: the run loop stops itself when the ant's cell index goes negative ("ant escaped the board"), i.e., the classic 2-state run ends after ~10,000 steps on default 150×150 unless you enlarge the grid — [moore-sof.langton-ant.min.js](https://langtonant.com/js/moore-sof.langton-ant.min.js)
- Storage is an `Int8Array` of size gridSize² (up to 25,000,000 cells at 5000×5000); rendering is Canvas 2D with 8-px cells, grid lines stroked once per reset (10,000 `moveTo/lineTo` segments at 5000), one `fillRect` per changed cell, the ant drawn as a filled triangle, and a live step counter formatted with `toLocaleString` — [moore-sof.langton-ant.min.js](https://langtonant.com/js/moore-sof.langton-ant.min.js)
- Telemetry shown: only a behavior swatch strip (colored chips with L/R icons) and the step count. No FPS, no steps/sec, no cell-count, no palette editor — [langtonant.com](https://langtonant.com/)
- A "links" box links the GitHub source plus Wikipedia articles for Langton's ant, Christopher Langton, Turing machine, and Alan Turing; the page loads Google Analytics (UA-56324561-2) — [langtonant.com](https://langtonant.com/)
- No `<meta name="viewport">` tag in the served HTML → the page is not mobile/responsive; no touch handlers, no zoom/pan, no keyboard shortcuts, no URL state, no export/save of any kind — [langtonant.com HTML](https://langtonant.com/)
- Data-quality bug found: in the "Steps per Refresh" dropdown the option labeled "100" has `value="10"`, so selecting 100 actually gives 10 steps/refresh — [langtonant.com HTML](https://langtonant.com/)

### Inferences
- Given the 2017 freeze and the reset-on-change design, any modern simulator with play/pause/step, live (non-destructive) option editing, and curated color palettes immediately exceeds this reference on every axis except raw grid size (5000×5000 is respectable).
- The random preset colors suggest the author treated color as incidental; a portfolio-grade app should treat palette design as a first-class feature (and Langton's ant art is the main viral appeal).

### Gaps
- I did not run the page in a browser, so pixel-level responsive behavior and the exact visual design (CSS file `css/site.min.css` was not fetched) are unverified; the HTML structure itself (fixed left panel, canvas below, no viewport meta) strongly indicates desktop-only layout.

## evolvecode.io/turmites — what it offers, tech stack, and provenance

### Takeaway
evolvecode.io/turmites is a genuinely capable vanilla-JS/Canvas **turmite** engine: full multi-state/multi-color rules edited as JSON, 12 well-chosen presets (including Busy Beavers and a drawing "Smiley Face"), 1–1024 ants with optional per-ant random rules, mouse zoom/pan with dirty-rect rendering, and a 1–100,000 steps/sec exponential speed slider. It is near-identical to the 11★ GitHub repo MaxRobinsonTheGreat/turmites (same index.html, same file quartet), ships with zero sharing/export/persistence, is mouse-only (no touch handlers), shows no measured stats or even a step counter, and spams console.log in production.

### Cited Findings
- Tech stack: plain HTML + CSS + two JS files (`presets.js`, `script.js`, ~1,750 lines total) with one full-window `<canvas>`; no framework, no build step, no dependencies; `<meta name="viewport">` is present — [index.html](https://evolvecode.io/turmites/index.html); [script.js](https://evolvecode.io/turmites/script.js)
- Provenance: GitHub repo [MaxRobinsonTheGreat/turmites](https://github.com/MaxRobinsonTheGreat/turmites) (11★, JavaScript, pushed 2026-07-30, description "langton's ant colony") contains the identical file quartet (index.html, presets.js, script.js, style.css); its raw index.html (7,352 bytes) matches the evolvecode.io page on every structural marker I checked (`antCanvas`, `controlPanel` minimized, `antCountInput`, `individualRulesCheck`, `randomizeOptionsPanel`, `simSpeedSlider`, "Start Position:", `editRuleBtn`) — [raw index.html](https://raw.githubusercontent.com/MaxRobinsonTheGreat/turmites/main/index.html); the repo's own GitHub Pages URL 404s ([maxrobinsonthegreat.github.io/turmites](https://maxrobinsonthegreat.github.io/turmites/)), while evolvecode.io serves a working deployment.
- Rule model: a mutable `rules` object keyed by state, each state holding one `{writeColor, move, nextState}` per color — i.e., a full (state × color → write, turn, next-state) machine; HALT is encoded as `nextState: -1`; per-ant `individualRule` objects override the global rules — [script.js](https://evolvecode.io/turmites/script.js)
- Move vocabulary (from code + the editor's comment header): relative `L` left, `R` right, `N` no turn, `U` u-turn, `S` stay in place (no move); absolute `^ > v <`; and `?` = random direction — [script.js](https://evolvecode.io/turmites/script.js)
- Rule editor: a `contenteditable` `<pre>` rendering the JSON with generated comment headers (state/color counts + move legend); Edit/Save(⭳)/Load(⭱) buttons — Save downloads a validated `turmite_rule.json` via Blob, Load reads a `.json` file and re-formats it into the editor; Apply parses (strips `//` comments, `JSON.parse`, alert on failure) and resets; Discard restores a `lastAppliedState` snapshot of every control — [index.html](https://evolvecode.io/turmites/index.html); [script.js](https://evolvecode.io/turmites/script.js)
- Presets (12 + Custom), defined with inline comments in `presets.js`: Langton's Ant, Constructor, Symmetrical, Snowflake, Smiley Face (a 15-step drawing program using absolute moves), Archimedes Spiral, Logarithmic Spiral, Square Filler, Simple Turing Machine, Busy Beaver 3, Busy Beaver 4, Busy Beaver 5 — [presets.js](https://evolvecode.io/turmites/presets.js)
- Multi-ant: Ants count input clamped to 1–1024; Start Position = Center / Random / Grid / Row; Start Direction = Up/Right/Down/Left/Random; "Individual Rules" checkbox (enabled only when >1 ant) gives each ant a random rule of random size; individual rules are preserved across resets — [index.html](https://evolvecode.io/turmites/index.html); [script.js](https://evolvecode.io/turmites/script.js)
- Randomize (hotkey F): generates a fresh random machine with Max States (input allows 1–1000) and Max Colors (2–12), and movement-type checkboxes (Relative on by default; Absolute; Random) — [index.html](https://evolvecode.io/turmites/index.html); [script.js](https://evolvecode.io/turmites/script.js)
- Speed: a single "Steps/Sec" slider (1–100) mapped linearly from 1 to 60 steps/sec at the midpoint and cubically-exponentially up to 100,000 steps/sec at max, with the computed target displayed next to it; the loop uses `setTimeout` scheduling with catch-up and a 100,000-steps-per-iteration safety cap; rendering is decoupled via `requestAnimationFrame` — [script.js](https://evolvecode.io/turmites/script.js)
- View: mouse-wheel zoom (0.1×–50×, anchored at cursor), drag-to-pan, Reset View button, `imageSmoothingEnabled=false` for crisp cells (re-enabled for the red anti-aliased circle ants); renders via a dirty-cell `Set` of `"x,y"` strings with full redraw only on view changes — [script.js](https://evolvecode.io/turmites/script.js)
- Grid semantics: the world is sized to the viewport (`ceil(width/scale)` columns) at init scale 8 and **wraps toroidally** (`(x+cols)%cols`); the grid dimensions are fixed at init and do not grow when zoomed out — [script.js](https://evolvecode.io/turmites/script.js)
- Colors: a hardcoded 12-color neon palette (black background, white, magenta, yellow, lime, cyan, red, orange, blue, hot pink, orchid, blueviolet); there is no UI to edit any color — [script.js](https://evolvecode.io/turmites/script.js)
- Hotkeys: Space = play/pause, R = reset, F = randomize (suppressed while typing in the rules editor); the control panel starts minimized with −/⚙ toggle buttons — [index.html](https://evolvecode.io/turmites/index.html); [script.js](https://evolvecode.io/turmites/script.js)
- Explicitly absent (verified by reading the entire script.js and index.html): no step-once button, no step counter, no measured steps/sec or FPS, no URL state/sharing, no image or GIF export, no localStorage persistence, no touch/touchstart/touchmove handlers (only wheel/mousedown/mousemove/mouseup/mouseleave), no highway detection, no ARIA/accessibility attributes, and ~60 `console.log` calls left in production code — [script.js](https://evolvecode.io/turmites/script.js); [index.html](https://evolvecode.io/turmites/index.html)
- Branding confusion: `<title>` is "Langton's Ant" and the panel header is "Langton's Ant Colony", although the engine is a general turmite machine — [index.html](https://evolvecode.io/turmites/index.html)

### Inferences
- evolvecode.io/turmites ≈ the deployed MaxRobinsonTheGreat/turmites app (the domain name "evolvecode" also rhymes with GitHub user "ivuecode", who owns a Unity Langton's Ant repo — plausible same author, unverified). Either way, the "second reference" the user wants to beat is an 11★ hobby repo with no README and a dead Pages URL.
- Its real strengths to match: the JSON rule format (complete state machines, not just LR strings), the busy-beaver/constructor preset curation, toroidal infinite-feeling wrap, and the decoupled sim/render loops with catch-up scheduling.
- Its exploitable weaknesses: everything around the engine — sharing, persistence, export, touch, stats, palette editing, accessibility, documentation — is missing, and the JSON-in-a-`contenteditable`-`<pre>` editor is developer-hostile, not user-friendly.

### Gaps
- I could not run the app, so mobile behavior (viewport is declared but handlers are mouse-only) is inferred from code, not observed. Whether MaxRobinson's `presets.js` differs from evolvecode's 12-preset file was not checked.

## Comparable implementations: feature inventory and standouts (top 10+)

### Takeaway
The field splits into (a) tiny vanilla demos with one or two good ideas, (b) one serious DSL+URL-sharing app (dwmkerr/langtonsant), and (c) the Golly ecosystem, which is the feature gold standard (web port included) but is Life-centric and overwhelming rather than ant-focused. No web turmite app combines custom-rule editing, sharing, export, mobile touch, stats, and documentation — each competitor has at most 2–3 of these.

## Common weaknesses across existing sims

### Takeaway
The category's weaknesses are consistent and structural: no persistence or sharing beyond one URL param, mouse-only input, developer-oriented rule entry (raw JSON/DSL) with no rule-space education, no measured telemetry, no export, and CPU-canvas performance ceilings — with langtonant.com additionally frozen since 2017 and resetting on every interaction.

### Cited Findings
- langtonant.com: no pause/step/reset; destructive reset on every option change; random (ugly) preset colors; custom rules restricted to L/R; non-wrapping fixed grid; no viewport meta (non-responsive); a value bug in its steps dropdown (labeled 100, acts as 10) — [langtonant.com](https://langtonant.com/); [min.js](https://langtonant.com/js/moore-sof.langton-ant.min.js)
- evolvecode.io/turmites: no URL state, no image/GIF export, no localStorage, no touch handlers, no step button/counter, no measured SPS/FPS, fixed 12-color palette with no editing, grid desyncs from zoom (sized at init scale only), production console.log spam, confusing "Individual Rules" flow (checkbox hides the global editor), JSON typing required of end users — [script.js](https://evolvecode.io/turmites/script.js); [index.html](https://evolvecode.io/turmites/index.html)
- Rule-entry UX across the field is developer-shaped: raw JSON (`contenteditable` pre) in evolvecode; a text DSL with grammar rules and error-throwing compiler in dwmkerr; "modify its properties" in mdciotti; numeric digit strings in Turm8 — [evolvecode](https://evolvecode.io/turmites/index.html); [dwmkerr README](https://raw.githubusercontent.com/dwmkerr/langtonsant/master/README.md); [mdciotti](https://mdciotti.github.io/turmites/); [turm8](https://tvil.itch.io/turm8)
- Persistence/sharing is nearly absent: only dwmkerr shares state via `?p=`; only t3rmit3 advertises save/load/share of rule configs; only antfarm ships an importable JSON gallery; evolvecode's save/load covers rules-as-files only, never full sim state — [dwmkerr](https://raw.githubusercontent.com/dwmkerr/langtonsant/master/README.md); [t3rmit3](https://github.com/screenseva/t3rmit3); [antfarm](https://github.com/Jmakesthingswith/antfarm-simulator); [evolvecode](https://evolvecode.io/turmites/script.js)
- No web simulator found implements highway detection/period discovery; the only project doing it (MrCamoga's distributed Java cluster) is desktop-only, and even the desktop animator (rrwick) treats highway search as a batch offline job — [MrCamoga README](https://github.com/MrCamoga/Langton-s-Ant); [rrwick README](https://github.com/rrwick/Langtons-Ant-Animator)
- Performance: every web entry is single-threaded CPU canvas; the serious-performance tools escape via GPU (glife3's WebGL2, claiming ~1000× CPU speed) or hashlife (copy.sh/life simulating patterns with trillions of cells) — [glife3 README](https://github.com/eruditor/glife3); [copy.sh/life](http://copy.sh/life/)
- Accessibility: no ARIA labels, canvas descriptions, or reduced-motion handling found on any surveyed page; several require fine mouse control with no keyboard alternative — [evolvecode index.html](https://evolvecode.io/turmites/index.html); [langtonant.com](https://langtonant.com/)
- Documentation of the rule space is missing everywhere: no surveyed sim explains the (states × colors) behavior taxonomy (highway/chaotic/builder classes), why ~10,000 steps matters for the classic ant, or what Busy Beaver presets mean; the busiest documentation is Wikipedia links — [langtonant.com links box](https://langtonant.com/); [mysimulator.uk](https://www.mysimulator.uk/langtons-ant/)

### Inferences
- These weaknesses form a coherent "portfolio-grade" checklist; because every competitor is missing at least half of it, a single app doing all of it wins by construction, not by any single hero feature.

## Gap analysis and prioritized "what would beat them" feature list

### Takeaway
Beat the references by combining evolvecode's rule depth, dwmkerr's sharing/gallery model, and Golly's rigor, then adding the four things nobody has: live-editable visual rule tables, seeded share URLs, measured telemetry + highway detection, and full touch/mobile support. Ranked below by (user value ÷ implementation cost).

### Cited Findings
(supporting facts for each priority, with sources)
- A visual state×color matrix editor is the clearest unmet need: the two references force users into raw JSON ([evolvecode](https://evolvecode.io/turmites/index.html)) or a text DSL ([dwmkerr README](https://raw.githubusercontent.com/dwmkerr/langtonsant/master/README.md)); no surveyed app renders the rule table itself.
- URL sharing precedent: dwmkerr's `?p=` param and its screenshot-plus-deeplink gallery is the pattern to copy ([README](https://raw.githubusercontent.com/dwmkerr/langtonsant/master/README.md)); neuroky's URL params prove the appetite for even cosmetic state ([neuroky](https://neuroky.me/turmites2.html)).
- Measured telemetry is cheap and absent: only neuroky shows FPS; evolvecode shows a target speed it may not meet; antfarm shows a stats overlay ([neuroky](https://neuroky.me/turmites2.html); [evolvecode script.js](https://evolvecode.io/turmites/script.js); [antfarm](https://github.com/Jmakesthingswith/antfarm-simulator)).
- Highway/period detection is the research-grade differentiator with a working non-web precedent (MrCamoga's distributed finder computing period/size/rotation) — [MrCamoga](https://github.com/MrCamoga/Langton-s-Ant).
- Export precedent exists only on desktop (rrwick's animator rendering supersampled animation frames; Golly reading/writing image formats) — [rrwick](https://github.com/rrwick/Langtons-Ant-Animator); [Golly features](https://golly.sourceforge.io/).
- Mobile/touch precedent: neuroky claims mobile support; native Golly ships iPad/Android apps — nobody in the web-turmite niche implements pinch-zoom/tap-place — [neuroky](https://neuroky.me/turmites2.html); [Golly news](https://golly.sourceforge.io/).
- Performance headroom benchmarks: glife3 (WebGL2, ~1000× CPU claim) and copy.sh/life (hashlife, 29201m-cell patterns) define the ceiling — [glife3](https://github.com/eruditor/glife3); [copy.sh/life](http://copy.sh/life/).

### Inferences — prioritized feature list for the expanded simulator
**Tier 1 — core "expanded and improved" (high value, low-to-medium cost):**
1. **Visual rule editor (state×color matrix table)** — dropdowns/toggles per cell for write-color, turn (L/R/N/U/S/absolute/random), next-state (incl. HALT); live re-parse into both the JSON format and a dwmkerr-compatible DSL string. Beats evolvecode (JSON-in-a-pre) and dwmkerr (grammar errors) simultaneously; this is the app's centerpiece.
2. **Seeded share URLs + localStorage persistence** — encode rule (JSON or DSL), ant count/placement, speed, palette, and view state in `?r=…&seed=…`; auto-save session to localStorage; "Copy link" and "Copy image" actions. Only dwmkerr has any of this, and only for the rule.
3. **Play / pause / step-once / reset with a proper speed governor** — step counter, target *and measured* steps/sec, FPS; catch-up scheduling like evolvecode's (`nextStepTime += stepDuration`, safety cap) — langtonant has none of these controls; evolvecode lacks step/counter.
4. **Touch/mobile parity** — pinch-zoom, one-finger pan, tap-to-place ants, responsive collapsible panel. No competitor has it; the viewport meta without handlers (evolvecode) shows the gap.
5. **Curated preset gallery with descriptions and deep links** — evolvecode's 12 presets (Busy Beavers, Constructor, Smiley Face) plus dwmkerr's gallery pattern (screenshot + one-click `?r=` URL), each with 2–3 sentences explaining expected behavior (highway at ~10k steps, Fibonacci spiral, etc.).

**Tier 2 — differentiation (high value, medium cost):**
6. **Export** — PNG snapshot first, then GIF/WebM recording of a step range (rrwick proves demand; zero web competitors).
7. **Highway detection** — repetition-window check on the ant's recent path/colormap with a "Highway! period N" badge; optionally auto-pause. Nonexistent in the web category; MrCamoga shows the algorithm.
8. **Multi-ant editing mode** — place/select/delete individual ants on canvas with per-ant rule assignment (evolvecode has per-ant random rules but pattern-based placement only; mdciotti has click-place but per-turmite not colony-scale).
9. **Palette + theme editor** — user-editable per-color swatches (fix langtonant's random colors and evolvecode's fixed 12), plus dark/light themes.
10. **Keyboard shortcuts + help overlay** — Space/R/F/step/zoom, `?` overlay listing them (evolvecode has 3 hotkeys and no help; neuroky sets the bar with its overlay).

**Tier 3 — polish and ceiling (medium value, higher cost):**
11. **In-app rule-space docs** — a "What am I looking at?" panel: states×colors counts, relative vs. absolute turmites, behavior classes, busy-beaver context, links (this audit's references). Nobody teaches the rule space.
12. **Performance mode** — typed-array grid (Int8/Uint8), dirty-rect rendering, optional Web Worker batching; stretch: WASM or WebGL2 hop like glife3 for 5000×5000+ grids at max speed.
13. **Undo/redo for board edits** (antfarm already does this; Golly's "unlimited undo/redo" is the standard).
14. **Import/export of full sessions as JSON** (antfarm's gallery model, extended to include palette + view + seed).

### Gaps
- Implementation-cost estimates are judgment calls from the codebase sizes I read (evolvecode ~1,750 LOC vanilla; dwmkerr is an Angular app with a compiler package), not measurements of the user's planned stack; no competitor pricing/effort data exists.
- Golly-web's turmite capabilities (whether RuleLoader can express turmites in the browser build) were not verified hands-on; its rule-family breadth in the web build is therefore conservatively marked "RuleLoader present, turmite support unverified."
